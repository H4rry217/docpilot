# DocPilot Block

DocPilot Block 是 DocPilot 的文档结构层。它把 Markdown 转成稳定的文档结构，让编辑器、后端服务和 AI 功能不必把整篇文档当作一段长字符串处理。

## 为什么需要它

Markdown 对人很友好，但对程序来说边界并不总是清晰。标题、表格、提示块、代码块、脚注这些内容有不同的含义，也需要不同的编辑和渲染方式。DocPilot Block 会给这些内容明确的类型、属性、子节点和身份标识，让系统可以更可靠地编辑、渲染、比较、搜索和转换文档。

这个模块不是可视化编辑器，也不是数据库。它更像是 Markdown 文本和上层应用能力之间的一层共同语言。

## 核心概念

### Block

Block 是文档里的主要结构单元，例如段落、标题、列表、表格、代码块、数学公式块、图表块、提示块、脚注定义、定义列表、目录标记、链接引用定义和原始 HTML 块。

一个 Block 可以包含：

- id，用来在处理过程中追踪同一个文档片段
- type，用来说明它是什么内容
- attrs，用来保存标题级别、代码语言、表格对齐方式、提示块类型、HTML 展示方式等信息
- 子 Block 或行内内容
- 来自原始 Markdown 的位置信息

### Inline 和 Mark

Inline 表示块内部的文本级内容，例如普通文本、换行、图片、行内数学公式、脚注引用、emoji 和行内 HTML。

Mark 表示覆盖在文本上的标记，例如加粗、斜体、删除线、行内代码、链接、下划线、插入、下标、上标和高亮。

这样拆分以后，模型会更清楚：Inline 说明“内容是什么”，Mark 说明“一段内容带有什么标记”。

### Typed View

基础 Block 模型比较通用，但有些场景需要更容易使用的形态。Typed View 会把常见结构包装成更明确的类型，例如标题、段落、表格、提示块、数学公式、图表和 HTML 块。

Typed View 不替代基础模型。它只是让已知结构更好用，同时保留扩展内容和暂未支持内容。

### 转换边界

DocPilot Block 目前负责三条重要边界：

- Markdown 转成结构化文档
- 结构化文档再渲染回 Markdown
- 结构化文档和编辑器使用的 JSON 结构互相转换

它的目标不是让所有 Markdown 扩展在往返后逐字不变，而是尽量保留文档含义，让已知结构明确化，并避免把暂时不认识的内容悄悄丢掉。

### 保留与兜底

当前模型覆盖的不只是基础 Markdown，也包括 front matter、表格、任务列表、数学公式、图表、提示块、脚注、定义列表、目录标记、链接引用定义、原始 HTML 和常见行内标记。

如果解析器遇到 DocPilot 还没有细化建模的内容，会把它放进扩展或未支持内容里，而不是直接丢弃。这样应用仍然可以展示、存储这些内容，也为后续升级模型留出空间。

### HTML 处理

原始 HTML 会被当作一种需要明确展示约定的内容。HTML 块会保留源码，并携带固定高度或自动高度、是否允许脚本、沙箱约束等展示属性。

默认策略是保守的：HTML 可以保留，但脚本执行和展示行为必须被明确声明，不能靠偶然行为发生。

## 它在项目里的位置

在当前项目中，DocPilot Block 是文档内容处理的共同语言。后端文档流程会使用它，编辑器边界也依赖它做结构转换。更上层的服务负责决定文档存在哪里、谁能访问、以及 AI 能力如何使用这些内容。

DocPilot Block 应该专注在文档结构本身。存储、认证、工作区权限和具体文件来源不属于它的职责。

## 当前职责

DocPilot Block 负责：

- 把 Markdown 解析成结构化文档
- 规范化文档结构和 Block 身份
- 把结构化文档渲染回 Markdown
- 在 Block 模型和编辑器 JSON 之间转换
- 为常见内容结构提供 Typed View
- 安全保留扩展内容和暂未支持内容

它不负责：

- 把文档保存到 MongoDB 或其他数据库
- 判断用户权限
- 挂载文件系统或读取外部文件
- 选择 AI prompt 或模型 provider
- 实现前端编辑器 UI

## 维护提示

新增文档概念时，要同时检查解析、渲染、Typed View、编辑器转换和 golden fixture。只要某种内容可能出现在用户 Markdown 里，就应该有一等模型，或者有明确的兜底表示方式。
